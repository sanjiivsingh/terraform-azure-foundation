# Storage Account Implicit Dependency Architecture

## Overview

This document describes the implementation of an implicit dependency between the Resource Group module and the Storage Account module.

Unlike explicit dependencies that use `depends_on`, implicit dependencies are automatically inferred by Terraform when one resource or module references outputs from another module.

This is the preferred Terraform design pattern because it allows Terraform to build the dependency graph automatically.

---

## Previous Approach

The Storage Account module was configured using an explicit dependency:

```hcl
module "storage_account" {
  source = "../../modules/storage_account"

  storage_accounts = var.storage_accounts

  depends_on = [
    module.resource_group
  ]
}
```

In this approach Terraform waits for the Resource Group module to complete before deploying the Storage Account module.

---

## New Approach

The Storage Account module consumes outputs generated by the Resource Group module.

Example:

```hcl
resource_group_name =
module.resource_group.resource_group_details["rg-dev-eastus"].name
```

Terraform automatically detects that the Storage Account module depends on the Resource Group module.

No `depends_on` statement is required.

---

## Dependency Flow

```text
Resource Group Module
        │
        ▼
Resource Group Outputs
        │
        ▼
Storage Account Module
```

---

## Benefits

### Reduced Configuration

No manual dependency declarations are required.

### Automatic Dependency Graph

Terraform constructs the dependency graph automatically.

### Improved Maintainability

Dependencies remain accurate as the infrastructure evolves.

### Enterprise Best Practice

Implicit dependencies are preferred over explicit dependencies whenever Terraform can infer the relationship.

---

## Conclusion

This implementation demonstrates Terraform's recommended dependency management strategy by using module outputs and references instead of manual dependency declarations.
